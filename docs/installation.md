# Installation, updates and recovery

[한국어](installation.ko.md). Read the [support matrix](support.md) and [measured verification](verification.md) before testing.

## Windows: no build tools required

Use an entire Windows x64 ZIP from a source you trust. Compare `Get-FileHash -Algorithm SHA256 <zip>` with that source's checksum. A checksum detects changed bytes; it does not prove publisher identity. This preview is unsigned. SmartScreen or organizational Application Control may block it. Do not disable security features: use an administrator-approved distribution or wait for an appropriately signed build.

Extract the ZIP before opening `memo-alarm-bridge.exe`. A local setup page opens; if it does not, paste the full `http://127.0.0.1:<port>/#bootstrap=...` link from the console into your browser. Keep that link private. Approve the session and review:

| Choice | Default / effect |
|---|---|
| Application folder | `%LOCALAPPDATA%\Programs\MemoAlarmBridge` |
| Private data | `%APPDATA%\MemoAlarmBridge\data`, separate from application files |
| Run without installing | Starts the PC workspace using its data folder; does not create a startup entry |
| Install / update | Copies checked immutable version files and switches `current.json` after validation |
| Sign-in startup | Off for a new installation; an existing setting is shown for review |
| Phone networking | New connection off; enable separately inside the app |

After installation, use `MemoAlarmBridge.exe` in the application folder. The workspace has its own approval link. An existing running Bridge can provide a fresh local link without restarting. Keep the Bridge process running for PC editing/sync. Phone alarms already prepared and registered are independent. Close the installer console when finished; closing only its browser tab does not stop the installer process.

## Android: prepare locally first

The `android-debug.apk` is development-only, signed with a disposable project-local key. A clean build can create a different key; it is not a stable update channel. The `android-unsigned.apk` needs your own deliberate signing process and cannot be installed directly. Review [building/signing](building.md). No production key is generated by the app or installer.

Transfer the chosen APK to your phone and explicitly approve that installation in Android. If Android requires allowing this installer source, review that source and revoke the temporary allowance afterward if desired. Managed-device policies may prohibit sideloading; do not bypass them. The project never installs a phone APK automatically.

Open Setup, allow **exact alarms**, allow **notifications**, and choose an installed **offline TTS voice**. If the system has no offline voice, install an appropriate system voice through its TTS settings, then return and recheck. Downloading a voice is a separate user action. Microphone permission is requested only when you choose to record a note; text notes and alarms work without it.

Use **Test in one minute**. Check the displayed phone state, audible playback, Stop and Snooze before pairing. Keep alarm volume at your chosen audible level. DND and the optional silent/vibrate preference still apply. The app does not request DND-policy access, force volume or show a full-screen takeover.

## Optional PC ↔ phone sync

1. Ensure the phone can reach the selected PC address. Same Wi-Fi can work if isolation/firewall rules allow it. A VPN is optional and must be configured separately by the user. No public tunnel is required by phone sync.
2. In PC Connection & setup, review an address/port and explicitly **Enable phone connection**. This creates a per-user protected TLS identity and remembers the choice for future starts. It does not change firewall, router or VPN settings.
3. If Windows asks about network access, inspect the program/network scope yourself. Prefer only the private network/address required by your devices. Avoid router port forwarding or exposing the loopback admin page.
4. Create a ten-minute invitation. On Android, paste the **entire string**, check the displayed endpoint and full certificate fingerprint against the PC, and confirm Pair. This creates a protected device credential and enables best-effort background sync.
5. Press **Sync now** and inspect pending edits, conflicts and each schedule's phone status. Background work is best effort, approximately every 15 minutes when connected, and can be delayed. It is not the alarm clock.

All paired devices can read and edit this collection. Pair only devices you trust. Revoking PC access or unpairing does **not** remove existing phone alarms. Cancel them explicitly on the phone when needed. A PC cancellation remains pending for an offline or revoked phone.

## Failure → recovery

| Symptom | What to do |
|---|---|
| Installer / executable blocked | Keep security enabled; use an approved/signed distribution. The development host reproduced an Application Control block. |
| Local approval link no longer works | Use the same browser session, or open the installed app for a fresh link. Do not paste the link into an issue. |
| `not_running` from CLI | Start the Bridge for the same `--data` directory. |
| Update says Bridge is running | Use the downloaded setup's Stop button; wait for exit, then retry. This does not stop prepared phone alarms. |
| Hash mismatch / damaged extraction | Retain your data and old version. Download and fully extract a new package, then recheck its checksum. |
| Disk full / migration validation failed | Free space for the package, temporary DB copy and retained backup. The old pointer and original DB are retained. Retry with a compatible package. |
| Damaged `current.json` or app binary | From a checked downloaded setup, uninstall **with data retained**, then reinstall. Do not delete the data folder. |
| Newer or corrupt DB | Keep the original and backups. Use the matching newer app or recover a known compatible snapshot while the Bridge is stopped. Do not create an empty replacement over the original. |
| Expired invitation / clocks differ | Correct device clocks and create a fresh invitation; a new one replaces the old invitation. |
| Phone cannot connect | Confirm endpoint, Wi-Fi isolation, private-network firewall policy and whether the PC is awake. Approve any network changes separately. Use manual sync after reconnecting. |
| Fingerprint changed / PC address changed | Stop and verify the change. Do not accept an unexpected pin. Follow the deliberate identity repair in the security guide and pair again. |
| `blocked_permission` | Review exact-alarm access and notification status in Setup, return to the app, and recheck. Unknown is not granted. |
| `blocked_audio` | Select an installed offline voice, check free space, and recheck preparation. An older working version may still be scheduled; its evidence is shown separately. |
| Conflict | Open Setup, compare both copies, and choose explicitly. Enabling a cancelled rule creates a new epoch. |
| APK signature mismatch | Keep the installed app. Do not automatically uninstall: Android uninstall erases local data. Obtain an APK signed with the same key, or deliberately preserve/sync important data before a fresh install. |

## Back up, update, uninstall

PC **Export local data** produces JSON records and phone reports. It does not contain the audio blobs, encrypted identity or all connection settings. For a full backup, stop the Bridge and copy the entire private data folder to a location you control. Keep its `blobs` folder and SQLite files together. These files contain private material; do not upload them to public issue trackers. DPAPI-protected keys are tied to the Windows account/machine and may not work after migration to another computer.

Updates are manual: extract the checked new ZIP, open its installer, stop the current Bridge and approve the update. Existing DBs get a consistent snapshot under `data/backups`; the candidate tests migration on a copy. The running app also takes a pre-schema-upgrade snapshot. Prior executable versions are retained. Do not roll an old executable back against a newer DB; use a compatible DB backup. Old version/staging/backup cleanup is manual so unexpected files are preserved.

Windows uninstall removes known executable/manifest files and this app's startup entry, preserving all private data and unknown files. It does not revoke or cancel phone alarms. Remove private data only as a separate, deliberate action after backing up what you need.

Android backup/cloud transfer is disabled for this app. There is no Android backup/restore UI in this preview. Android uninstall clears local notes, recordings and schedules. Keep important information on the paired PC or copy it out before any deliberate uninstall; do not assume OS backup will recover it.
